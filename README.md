# Дипломный проект: Автоматизация тестирования маркетплейса 21vek.by

Профессиональный фреймворк для сквозного (E2E), мобильного и API тестирования крупного ритейл-портала. Проект построен на базе современных стандартов QA-инженерии с использованием паттерна Page Object Model (POM).

## 🛠 Технологический стек
* Язык программирования: Python 3.12
* Ядро автоматизации: Playwright (Python-библиотека)
* Тестовый движок: Pytest
* Отчетность: Allure Report / Pytest HTML Report
* Архитектурный паттерн: Page Object Model (POM)

---

## 📊 Структура тест-дизайна и покрытые риски (Всего: 46 тест-кейсов)

Проект разделен на 5 изолированных модулей, каждый из которых страхует критически важные бизнес-цепочки маркетплейса:

1. **Модуль Поиска (tests/test_search.py) — 25 тестов**
   * *Проверки:* Масштабный позитивный поиск по параметризованной матрице реальных товаров (22 шт.) + негативные сценарии ввода некорректных данных (спецсимволы, абракадабра).
   * *Бизнес-риск:* Сбой поисковой выдачи напрямую ведет к потере конверсии и уходу покупателей.

2. **Модуль Корзины (tests/test_cart.py) — 6 тестов**
   * *Проверки:* Добавление товаров, контроль уникальных сессий, калькулятор цен (динамический пересчет суммы при изменении количества кнопкой «+»), очистка корзины и навигация возврата к покупкам.
   * *Бизнес-риск:* Ошибки на этапе оформления заказа — критический риск остановки продаж.

3. **Модуль Мобильного Адаптива (tests/test_adaptive.py) — 4 теста**
   * *Проверки:* Эмуляция экрана смартфона (iPhone 14), доступность адаптивного меню шапки («гамбургер») и корректность мобильной поисковой выдачи.
   * *Бизнес-риск:* Потеря более 70% мобильного трафика при съезжании верстки UI.

4. **Модуль Навигации и Брендов (tests/test_navigation.py / test_product_card.py) — 10 тестов**
   * *Проверки:* Сквозные переходы по разделам «Акции», «Доставка», «Оплата», кликабельность главного логотипа, а также доступность товарных листингов популярных брендов (Apple, LG).
   * *Бизнес-риск:* Сломанные сквозные ссылки нарушают пользовательский опыт (UX) и SEO-оптимизацию сайта.

5. **Интеграционный модуль Backend API (tests/test_api.py) — 1 тест**
   * *Проверки:* Прямой сетевой запрос к реальному публичному API-эндпоинту каталога смартфонов маркетплейса с валидацией статус-кода 200 OK и структуры данных.
   * *Бизнес-риск:* Падение или некорректные ответы серверного бэкенда при исправном визуальном интерфейсе.
