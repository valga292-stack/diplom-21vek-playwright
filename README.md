# Дипломный проект по автоматизации QA (Маркетплейс 21vek.by)

Добрый день, меня зовут Валерий и это мой выпускной дипломный проект после прохождения 4-месячного курса «Специалист по QA». 

До начала обучения я почти ничего не знал про автоматизацию и тестирование. Весь фреймворк я написал самостоятельно с нуля, используя лекции курса, профильную литературу, разборы на Хабре и помощь ИИ-ассистента, который помогал мне разбираться со сложным синтаксисом и направлял архитектуру.

## 🚀 Что под капотом (Стек технологий)
* Язык: Python 3.12 (базовые основы изучал параллельно с курсом)
* Инструмент: Playwright (выбрал его вместо Selenium, так как он быстрее и стабильнее работает с динамическим веб-сайтом)
* Запуск тестов: Pytest
* Отчеты: Allure Report + pytest-html

---

## 🛠️ Как устроена архитектура проекта

Проект спроектирован по каноничному паттерну Page Object Model (POM). Я постарался строго разделить логику, чтобы код было легко читать и поддерживать:
1. pages/ — здесь лежат только локаторы и технические действия со страницами (клики, ввод текста). Все локаторы я писал вручную.
2. tests/ — здесь находятся сами сценарии тестов и конкретные проверки (assert). 

### Мои инженерные решения для повышения балла (Выход за рамки ТЗ):
* Оптимизация и Тест-дизайн: Чтобы не копировать один и тот же код, я применил @pytest.mark.parametrize. Создал большую матрицу данных на 26 различных товаров, категорий и негативных сценариев (поиск опечаток).
* Тестирование API: Написал отдельный изолированный тест через библиотеку requests, который быстро проверяет доступность бэкенда до запуска тяжелых браузерных тестов.
* Работа с Базами Данных (БД): В conftest.py реализовал сессионную фикстуру, которая через SQL-запросы создает базу SQLite в памяти и логирует время старта тестов.
* Докеризация: Написал Dockerfile для запуска тестов в изолированном контейнере.
* CI/CD пайплайн: Настроил автоматический запуск тестов в облаке через GitHub Actions на базе Ubuntu Linux.

## 🛑 Сложные кейсы и проблемы, которые я решил:
1. Капризная верстка и блокировки: Стандартные клики Playwright иногда падали по таймауту на кнопке корзины из-за динамической рекламы на сайте 21vek.by. Я решил эту проблему, настроив принудительный клик напрямую через JavaScript (dispatch_event("click")).
2. Anti-Bot защита сайта: При частых запусках реальный сайт маркетплейса начинает блокировать IP-адрес (выдает ошибку Connection Reset или Timeout). В коде фреймворка всё настроено верно, а для стабильного локального прогона я рекомендую переключаться на динамический мобильный интернет.
3. Настройка запуска: Все флаги отчетов и логирования я зашил в pytest.ini, выполнив требование запуска «в один клик».

## 💻 Инструкция по запуску

Проект настроен так, чтобы запускаться без длинных инструкций.

1. Установите зависимости:
  
   pip install -r requirements.txt
   
2. Установите браузеры Playwright:
  
   python -m playwright install
   
3. Запустите тесты одной командой из корня проекта:
  
   python -m pytest
